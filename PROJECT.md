# 1. Назначение проекта

AquaControl Pro — полностью автономное Android-приложение для контроля сроков замены картриджей бытовых фильтров воды.

Основная идея проекта — избавить пользователя от необходимости помнить, когда необходимо заменить картридж.

В отличие от обычных напоминаний календаря приложение хранит информацию непосредственно о фильтрах и автоматически рассчитывает срок замены с учетом условий эксплуатации.

Приложение работает полностью локально.

Сервер отсутствует.

Регистрация отсутствует.

Интернет не требуется.

---

# 2. Основные возможности

На текущий момент приложение поддерживает:

- несколько объектов (квартира, дача, родители и т.д.);
- несколько фильтров внутри каждого объекта;
- автоматический расчет срока службы;
- учет количества пользователей;
- учет жесткости воды;
- историю замен;
- учет расходов;
- быстрый переход к покупке картриджа;
- локальные уведомления Android;
- работу без подключения к Интернету;
- хранение всех данных только на устройстве.

## Резервная копия

Экспорт сохраняет содержимое localStorage в обычный JSON-файл.

Используется стандартное системное окно сохранения Android
(Storage Access Framework, Intent.ACTION_CREATE_DOCUMENT).

Дополнительные Capacitor-плагины не используются.

Схема работы:

```
JavaScript (index.html)
    │ window.AquaExport.saveBackup(json, fileName)
    ▼
MainActivity.java (JavascriptInterface "AquaExport")
    │ ACTION_CREATE_DOCUMENT
    ▼
Системное окно сохранения Android
    │ пользователь выбирает папку или облако
    ▼
onActivityResult → запись файла
    │ window.onBackupSaveResult(ok, message)
    ▼
Toast в приложении
```

Имя файла формируется автоматически:

```
aquacontrol-backup-ГГГГ-ММ-ДД-ЧЧММ.json
```

Дата и время в имени не дают копиям перезаписывать друг друга.

Если нативный мост недоступен (старая сборка APK), приложение показывает
запасное окно с текстом для копирования вручную.

В обычном браузере файл скачивается стандартным способом.

Импорт выполняется через обычный `<input type="file">`,
нативный код для импорта не требуется.

# 10. Структура базы данных

Общий формат:

```json
{
  "currentLocationId": "loc1",
  "currentFilterId": "f1",
  "locations": [],
  "filters": [],
  "history": []
}
```

## currentLocationId

Идентификатор выбранного объекта.

Используется для открытия приложения именно на последнем выбранном объекте.

---

## currentFilterId

Идентификатор активного фильтра.

После запуска пользователь видит тот фильтр, который был открыт последним.

---

## locations

Массив объектов.

Пример:

```json
{
    "id": "loc1",
    "name": "Моя квартира"
}
```

Каждый объект может содержать любое количество фильтров.

---

## filters

Основной массив приложения.

Каждый элемент описывает один фильтр.

Пример:

```json
{
    "id":"f1",
    "locationId":"loc1",
    "name":"Кувшин",
    "type":"Кувшин",
    "baseDays":60,
    "cycleMs":null,
    "people":2,
    "hardness":1,
    "lastDate":1710000000000,
    "brand":"Аквафор",
    "buyUrl":"https://..."
}
```

Описание полей.

| Поле | Назначение |
|------|------------|
| id | идентификатор фильтра |
| locationId | объект, которому принадлежит фильтр |
| name | название фильтра |
| type | тип фильтра |
| baseDays | паспортный срок службы |
| cycleMs | ускоренный тестовый режим |
| people | количество пользователей |
| hardness | коэффициент жесткости воды |
| lastDate | дата последней замены |
| brand | модель картриджа |
| buyUrl | ссылка на магазин |

---

## history

История замен.

Каждая запись содержит:

```json
{
    "filterName":"Кувшин",
    "date":"15.03.2026",
    "cost":450,
    "note":""
}
```

Используется для:

- истории замен;
- подсчета расходов;
- расчета экологической статистики.

# 11. Расчет срока службы

Приложение автоматически рассчитывает реальный срок службы фильтра.

Используются два коэффициента.

## Количество пользователей

```
1 человек = 1.00

2 человека = 0.75

3–4 человека = 0.50
```

---

## Жесткость воды

```
Мягкая = 1.00

Жесткая = 1.25

Очень жесткая = 1.50
```

---

Итоговый расчет:

```
resourceDays =
round(
baseDays
× peopleMultiplier
× (1 / hardness)
)
```

После расчета определяется дата окончания ресурса.

```
expiryDate =
lastDate
+
resourceDays
```

Количество оставшихся дней:

```
daysLeft =
ceil(
(expiryDate - now)
/ 86400000
)
```

---

# 12. Тестовый режим

Для проверки уведомлений используется ускоренный режим.

В этом режиме применяется поле:

```
cycleMs
```

Возможные значения:

- 1 минута
- 5 минут
- 1 час

Если используется тестовый режим:

- коэффициенты пользователей не учитываются;
- жесткость воды не учитывается;
- ресурс берется напрямую из cycleMs.

Это позволяет быстро проверить уведомления без ожидания нескольких месяцев.

## Панель действий и настройки

Действия с фильтром вынесены в одну строку значков:

| Значок | Действие |
|--------|----------|
| ✏️ | изменить фильтр |

| ⚙️ | настройки |
| 🗑 | удалить фильтр |

Раздел «Настройки» содержит:

- сохранение резервной копии;
- восстановление из файла;
- подсказку о резервных копиях;
- номер версии.

Раньше эти пункты были отдельными кнопками на главном экране
и занимали много места. Теперь главный экран помещается
без прокрутки.

---

## Переключение между домами

Доступны три способа:

1. Кнопка с названием дома вверху (список домов) — прежний способ.
2. Свайп влево или вправо по экрану.
3. Точки внизу экрана — показывают количество домов
   и текущий, по ним можно нажимать.

Точки и свайп появляются только когда домов больше одного.

Свайп намеренно не срабатывает:

- на горизонтальной ленте вкладок фильтров;
- внутри модальных окон и подсказок;
- в полях ввода;
- при вертикальной прокрутке;
- при слишком коротком (менее 55 px) или медленном (более 0.7 с) жесте.

Переключение зациклено: после последнего дома идет первый.

# 15. Локальные уведомления

Для уведомлений используется нативный Android-плагин:

```
@capacitor/local-notifications
```

Уведомления работают полностью локально.

Подключение к Интернету не требуется.

---

## Логика работы

Для каждого фильтра создаются два уведомления.

### Первое уведомление

Отправляется в момент окончания срока службы.

Текст:

```
Пора заменить фильтр
```

---

### Второе уведомление

Если пользователь не заменил картридж, приложение автоматически создает повторное напоминание.

Обычный режим:

через 7 дней.

Тестовый режим:

через один дополнительный цикл.

---

## Экран настройки разрешений

Android агрессивно усыпляет фоновые приложения, поэтому напоминания
могут не приходить, пока пользователь не снимет ограничения.

В приложении есть экран «Настроить уведомления».

Экран проверяет три разрешения:

1. показ уведомлений;
2. работа без ограничений батареи;
3. автозапуск после перезагрузки.

Что он делает:

- определяет производителя устройства через нативный мост;
- показывает инструкцию именно для этой прошивки;
- открывает нужный экран системных настроек одной кнопкой;
- отмечает галочкой уже выданные разрешения.

Поддерживаются подсказки для Xiaomi, Redmi, POCO, Huawei, Honor,
OPPO, realme, vivo, iQOO, Samsung, Meizu, ASUS.
Для остальных показывается общая инструкция.

Экран открывается автоматически при первом запуске,
а также вручную кнопкой «🔔 Настроить уведомления».

Если разрешение на отключение экономии батареи уже выдано,
экран при следующих запусках не появляется.

Кнопка «Больше не показывать» отключает автопоказ навсегда.

---

## Перестроение расписания

Одновременно может существовать только одно актуальное расписание уведомлений.

Для предотвращения гонок используется очередь Promise.

Основные функции:

```
scheduleAllFilterNotifications()
```

и

```
runScheduleJob()
```

Сначала удаляются все ожидающие уведомления.

После этого создается новое расписание.

---

## Когда выполняется перестроение

Только после изменения данных.

Например:

- замена фильтра;
- перенос срока;
- изменение параметров фильтра;
- создание фильтра;
- удаление фильтра;
- создание объекта;
- удаление объекта.

---

Не выполняется:

- при открытии приложения;
- при сворачивании приложения;
- при возврате из фона.

Именно это изменение устранило проблему двойных уведомлений в версии 1.0.19.

| showHelp() | отображение подсказок |
| showCustomConfirm() | модальное подтверждение |
| drawWaves() | анимация фона |

# 20. Известные ограничения

На текущий момент известны следующие ограничения.

## После перезагрузки телефона

Восстановление расписания работает.

Оно обеспечивается штатным механизмом плагина
`@capacitor/local-notifications`: приемник
`LocalNotificationRestoreReceiver` ловит `BOOT_COMPLETED`
и перепланирует уведомления. Собственный код для этого не требуется.

Уведомления, срок которых наступил, пока телефон был выключен,
показываются примерно через 15 секунд после загрузки.

**Важное ограничение.**

На прошивках Xiaomi, Huawei, OPPO, vivo, Samsung и подобных
автозапуск по умолчанию запрещен, и восстановление не сработает,
пока пользователь не выдаст разрешения вручную.

Проверено на практике: без разрешений уведомление после перезагрузки
не приходит, с разрешениями — приходит стабильно.

Для решения добавлен экран «Настроить уведомления» (см. раздел 15).

---

## Экспорт

Реализован полноценный экспорт в файл через стандартное системное окно сохранения Android.

Текстовый режим с копированием вручную сохранен только как запасной вариант
для старых сборок и для запуска в обычном браузере.

---

## Светлая тема

Пока отсутствует.

Темная тема считается основной.

---

## iOS

Поддержка не планируется.

Проект ориентирован исключительно на Android.

Каждая версия должна содержать небольшое количество изменений.

Разделение на множество файлов не выполняется без необходимости.
