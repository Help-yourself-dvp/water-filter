# 1. Назначение проекта

AquaControl Pro — полностью автономное Android-приложение для контроля сроков замены картриджей бытовых фильтров воды.

Основная идея проекта — избавить пользователя от необходимости помнить, когда необходимо заменить картридж.

В отличие от обычных напоминаний календаря приложение хранит информацию непосредственно о фильтрах и автоматически рассчитывает срок замены с учетом условий эксплуатации.

Приложение работает полностью локально.

Сервер отсутствует.

Регистрация отсутствует.

Интернет не требуется.

---

# 2. Основные возможности

На текущий момент приложение поддерживает:

- несколько объектов (квартира, дача, родители и т.д.);
- несколько фильтров внутри каждого объекта;
- автоматический расчет срока службы;
- учет количества пользователей;
- учет жесткости воды;
- историю замен;
- учет расходов;
- быстрый переход к покупке картриджа;
- локальные уведомления Android;
- работу без подключения к Интернету;
- хранение всех данных только на устройстве.

---

## release.yml

Релизный GitHub Workflow. Запускается только вручную:
Actions → «Build Release APK (RuStore)» → Run workflow.

Ограничение GitHub: кнопка «Run workflow» для этого файла появится только после того,
как он попадёт в основную ветку `main`. В рабочей ветке файл лежит и проверен,
но запустить его вручную нельзя.

Повторяет все шаги `build.yml` и дополнительно:

- берёт `versionName` и `versionCode` из `version.json`;
- проверяет, что версия в `index.html` совпадает с `version.json`;
- падает, если в репозитории нет секрета с ключом подписи;
- прописывает ключ подписи прямо в `signingConfigs` в `android/app/build.gradle`;
- собирает `assembleRelease`;
- печатает отпечаток сертификата SHA-256 и проверяет отсутствие `android:debuggable`;
- публикует APK в GitHub Releases.

Файл создан отдельно от `build.yml` намеренно: рабочая сборка не должна ломаться
из-за экспериментов с релизной.

## Резервная копия

Экспорт сохраняет содержимое localStorage в обычный JSON-файл.

Используется стандартное системное окно сохранения Android
(Storage Access Framework, Intent.ACTION_CREATE_DOCUMENT).

Дополнительные Capacitor-плагины не используются.

Схема работы:

```
JavaScript (index.html)
    │ window.AquaExport.saveBackup(json, fileName)
    ▼
MainActivity.java (JavascriptInterface "AquaExport")
    │ ACTION_CREATE_DOCUMENT
    ▼
Системное окно сохранения Android
    │ пользователь выбирает папку или облако
    ▼
onActivityResult → запись файла
    │ window.onBackupSaveResult(ok, message)
    ▼
Toast в приложении
```

Имя файла формируется автоматически:

```
aquacontrol-backup-ГГГГ-ММ-ДД-ЧЧММ.json
```

Дата и время в имени не дают копиям перезаписывать друг друга.

Если нативный мост недоступен (старая сборка APK), приложение показывает
запасное окно с текстом для копирования вручную.

В обычном браузере файл скачивается стандартным способом.

Импорт выполняется через обычный `<input type="file">`,
нативный код для импорта не требуется.

## filters

Основной массив приложения.

Каждый элемент описывает один фильтр.

Пример:

```json
{
    "id":"f1",
    "locationId":"loc1",
    "name":"Кувшин",
    "type":"Кувшин",
    "baseDays":60,
    "cycleMs":null,
    "people":2,
    "hardness":1,
    "lastDate":1710000000000,
    "brand":"Аквафор",
    "buyUrl":"https://..."
}
```

Описание полей.

| Поле | Назначение |
|------|------------|
| id | идентификатор фильтра |
| locationId | объект, которому принадлежит фильтр |
| name | название фильтра |
| type | тип фильтра |
| baseDays | паспортный срок службы |
| cycleMs | ускоренный тестовый режим |
| people | количество пользователей |
| hardness | коэффициент жесткости воды |
| lastDate | дата последней замены |
| brand | модель картриджа |
| buyUrl | ссылка на магазин |

# 11. Расчет срока службы

Приложение автоматически рассчитывает реальный срок службы фильтра.

Используются два коэффициента.

## Количество пользователей

```
1 человек = 1.00

2 человека = 0.75

3–4 человека = 0.50
```

---

## Жесткость воды

```
Мягкая = 1.00

Жесткая = 1.25

Очень жесткая = 1.50
```

---

Итоговый расчет:

```
resourceDays =
round(
baseDays
× peopleMultiplier
× (1 / hardness)
)
```

После расчета определяется дата окончания ресурса.

```
expiryDate =
lastDate
+
resourceDays
```

Количество оставшихся дней:

```
daysLeft =
ceil(
(expiryDate - now)
/ 86400000
)
```

# 12. Тестовый режим

Для проверки уведомлений используется ускоренный режим.

С версии 1.0.29 он **скрыт от обычного пользователя**: варианты «1 мин», «5 мин», «1 час»
появляются в списке сроков только после включения режима проверки —
семь нажатий на строку с версией в разделе «О приложении».

В ускоренном режиме напоминания приходят точно в рассчитанный момент,
без переноса на удобный час.

В этом режиме применяется поле:

```
cycleMs
```

Возможные значения:

- 1 минута
- 5 минут
- 1 час

Если используется тестовый режим:

- коэффициенты пользователей не учитываются;
- жесткость воды не учитывается;
- ресурс берется напрямую из cycleMs.

Это позволяет быстро проверить уведомления без ожидания нескольких месяцев.

## Переключение между домами

Доступны три способа:

1. Кнопка с названием дома вверху — открывает окно «Мои дома»,
   где можно переключиться, переименовать, удалить и добавить дом.
2. Свайп влево или вправо по экрану.
3. Точки внизу экрана — показывают количество домов
   и текущий, по ним можно нажимать.

Точки и свайп появляются только когда домов больше одного.

Свайп намеренно не срабатывает:

- на горизонтальной ленте вкладок фильтров;
- внутри модальных окон и подсказок;
- в полях ввода;
- при вертикальной прокрутке;
- при слишком коротком (менее 55 px) или медленном (более 0.7 с) жесте.

Переключение зациклено: после последнего дома идет первый.

# 15. Локальные уведомления

Для уведомлений используется нативный Android-плагин:

```
@capacitor/local-notifications
```

Уведомления работают полностью локально.

Подключение к Интернету не требуется.

---

## Логика работы

Для каждого фильтра создаются до трёх уведомлений.

Все они переносятся на начало выбранного промежутка суток
(«Настройки» → «Когда напоминать»): утро 9:00–12:00 (по умолчанию),
день 14:00–17:00, вечер 19:00–21:00.

Промежуток, а не точное время, выбран сознательно: Android в спящем режиме
может показать напоминание позже запланированной минуты, и обещать точную
минуту было бы нечестно. Уведомление ставится на начало промежутка,
поэтому даже с задержкой оно приходит в разумное время.

### Предупреждение заранее

За выбранное количество дней до конца срока (по умолчанию 7, можно 3, 14 или отключить).

```
Скоро замена фильтра
«Кувшин Кухня» [Моя квартира] — осталось 7 дн. Самое время купить картридж.
```

---

### Основное уведомление

В день окончания срока службы.

```
Пора заменить фильтр
```

---

### Повторное уведомление

Если картридж не заменён — через 7 дней после окончания срока.

```
Фильтр всё ещё не заменён
```

В ускоренном (тестовом) режиме предупреждение заранее не создаётся,
а оба остальных приходят точно в расчётное время, без переноса на выбранный час.

---

## Экран настройки разрешений

Android агрессивно усыпляет фоновые приложения, поэтому напоминания
могут не приходить, пока пользователь не снимет ограничения.

В приложении есть экран «Настроить уведомления».

Экран проверяет три разрешения:

1. показ уведомлений;
2. работа без ограничений батареи;
3. автозапуск после перезагрузки.

Что он делает:

- определяет производителя устройства через нативный мост;
- показывает инструкцию именно для этой прошивки;
- открывает нужный экран системных настроек одной кнопкой;
- отмечает галочкой уже выданные разрешения.

Поддерживаются подсказки для Xiaomi, Redmi, POCO, Huawei, Honor,
OPPO, realme, vivo, iQOO, Samsung, Meizu, ASUS.
Для остальных показывается общая инструкция.

Экран открывается автоматически при первом запуске,
а также вручную кнопкой «🔔 Настроить уведомления».

Если разрешение на отключение экономии батареи уже выдано,
экран при следующих запусках не появляется.

Кнопка «Больше не показывать» отключает автопоказ навсегда.

---

## Перестроение расписания

Одновременно может существовать только одно актуальное расписание уведомлений.

Для предотвращения гонок используется очередь Promise.

Основные функции:

```
scheduleAllFilterNotifications()
```

и

```
runScheduleJob()
```

Сначала удаляются все ожидающие уведомления.

После этого создается новое расписание.

---

## Когда выполняется перестроение

Только после изменения данных.

Например:

- замена фильтра;
- перенос срока;
- изменение параметров фильтра;
- создание фильтра;
- удаление фильтра;
- создание объекта;
- удаление объекта.

---

Не выполняется:

- при открытии приложения;
- при сворачивании приложения;
- при возврате из фона.

Именно это изменение устранило проблему двойных уведомлений в версии 1.0.19.

При нажатии на уведомление приложение автоматически:

- открывает нужный объект;
- выбирает соответствующий фильтр;
- показывает окно замены картриджа.

Пользователю не требуется самостоятельно искать фильтр.

# 18. Подпись приложения

Используется постоянный:

```
debug.keystore
```

Он хранится в GitHub Secrets.

Имя секрета:

```
DEBUG_KEYSTORE_BASE64
```

Ключ нестандартный (CN=AquaControlPro), срок действия 30 лет.
Несмотря на имя файла, это полноценный ключ подписи, пригодный и для релизных сборок,
и для публикации в магазине.

---

Использование постоянной подписи позволяет:

- устанавливать новые версии поверх старых;
- сохранять всю пользовательскую информацию;
- не удалять приложение при обновлении.

---

## Важно

Workflow

```
generate-keystore.yml
```

использовался только один раз.

Повторный запуск запрещен.

Создание нового ключа приведет к несовместимости всех следующих APK с уже установленными версиями приложения.

---

## Резервная копия ключа (критично)

Ключ существует в двух местах: в секрете репозитория и в скачанном артефакте сборки.
Артефакты GitHub Actions хранятся ограниченное время.

**Владелец обязан хранить копию `debug.keystore` вне GitHub** (облако + офлайн-носитель).

Потеря ключа означает: обновление уже установленных копий приложения станет невозможным
навсегда, а в магазине придётся публиковать приложение как новое, с потерей всех пользователей
и их данных.

---

## Контроль подписи в релизной сборке

`release.yml`:

- падает, если секрета с ключом нет (иначе Gradle подписал бы APK случайным ключом);
- прописывает ключ явно в `signingConfigs` в `android/app/build.gradle`
  (Android Gradle Plugin может проигнорировать ключ, лежащий в `~/.android/`);
- печатает отпечаток сертификата SHA-256 — он обязан совпадать во всех версиях;
- проверяет отсутствие `android:debuggable` в собранном APK.

Сравнивать нужно именно отпечаток сертификата. Хэш файла `META-INF/CERT.RSA`
для контроля не годится: он содержит метку времени подписи и меняется при каждой сборке.

# 20. Известные ограничения

На текущий момент известны следующие ограничения.

## После перезагрузки телефона

Восстановление расписания работает.

Оно обеспечивается штатным механизмом плагина
`@capacitor/local-notifications`: приемник
`LocalNotificationRestoreReceiver` ловит `BOOT_COMPLETED`
и перепланирует уведомления. Собственный код для этого не требуется.

Уведомления, срок которых наступил, пока телефон был выключен,
показываются примерно через 15 секунд после загрузки.

**Важное ограничение.**

На прошивках Xiaomi, Huawei, OPPO, vivo, Samsung и подобных
автозапуск по умолчанию запрещен, и восстановление не сработает,
пока пользователь не выдаст разрешения вручную.

Проверено на практике: без разрешений уведомление после перезагрузки
не приходит, с разрешениями — приходит стабильно.

Для решения добавлен экран «Настроить уведомления» (см. раздел 15).

---

## Экспорт

Реализован полноценный экспорт в файл через стандартное системное окно сохранения Android.

Текстовый режим с копированием вручную сохранен только как запасной вариант
для старых сборок и для запуска в обычном браузере.

---

## Светлая тема

Пока отсутствует.

Темная тема считается основной.

---

## iOS

Поддержка не планируется.

Проект ориентирован исключительно на Android.

- лента вкладок фильтров листается как раньше.

# 23. Правила разработки

Для проекта приняты следующие правила.

---

## Одно изменение — одна версия

Каждая версия должна содержать небольшое количество изменений.

Это значительно упрощает поиск ошибок.

---

## Сначала стабильность

# 24. Версионность и выпуск версий

## Единый источник версии

Файл `version.json`:

```json
{
  "versionName": "1.0.28",
  "versionCode": 29
}
```

Правила:

- `versionCode` — целое число, растёт строго на 1 при каждом выпуске.
  Android отказывается устанавливать APK, у которого код версии меньше или равен установленному.
- `versionName` — то, что видит пользователь («1.0.28»).
- Тот же номер продублирован в `index.html` в элементе `id="appVersionTag"`.
  Релизная сборка сравнивает обе строки и падает при расхождении —
  это защита от типичной ошибки «забыли обновить версию в интерфейсе».

Старый `build.yml` пока берёт номера из жёстко прописанных команд `sed` —
это исторический вариант, он оставлен без изменений намеренно.

## Обновление поверх предыдущей версии

Условия, при которых обновление устанавливается без удаления приложения:

1. Тот же `packageName` (`com.aquacontrol.pro`).
2. Тот же ключ подписи (см. раздел 18).
3. Больший `versionCode`.

Данные пользователя (`localStorage`, ключ `aquaControlProDB`) при таком обновлении сохраняются.

Проверка перед каждым выпуском: установить новый APK поверх старого на реальном телефоне
и убедиться, что список объектов, фильтров и история на месте.

## Порядок выпуска

1. Одна версия — одна небольшая законченная задача.
2. Правки в `index.html`.
3. Обновить `version.json` (обе величины) и строку версии в `index.html`.
4. Дополнить `CHANGELOG.md`.
5. Merge в `main`.
6. Actions → «Build Release APK (RuStore)» → Run workflow.
7. Проверить в логе: отпечаток сертификата не изменился, `debuggable` отсутствует.
8. Установить APK поверх на телефоне, пройти чеклист из раздела 21.
9. Загрузить версию в магазин (см. `RUSTORE.md`).

# 25. Публикация в магазине

Подробная инструкция, готовые тексты карточки и чеклист — в файле `RUSTORE.md`.

Обязательный минимум для RuStore:

- релизная подписанная сборка APK, `debuggable` отсутствует;
- `targetSdkVersion` не ниже 28 (сейчас 34);
- растущий `versionCode`, неизменный ключ подписи;
- политика конфиденциальности по публичному адресу
  https://help-yourself-dvp.github.io/water-filter/privacy.html
  и ссылкой внутри приложения;
- email поддержки;
- иконка 512×512 и не менее четырёх скриншотов;
- описание на русском: краткое до 80 символов, полное до 4000;
- каждое запрашиваемое разрешение объяснимо одной фразой.
