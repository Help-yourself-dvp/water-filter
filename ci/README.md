# Файлы, которые нужно перенести в .github/workflows/

Здесь лежат готовые сборочные файлы. Они **не работают**, пока находятся в папке `ci/`:
GitHub Actions видит только `.github/workflows/`.

| Файл | Что делает | Куда положить |
|---|---|---|
| `build.yml` | отладочная сборка APK для проверки на своём телефоне | `.github/workflows/build.yml` (заменить существующий) |
| `release.yml` | релизная подписанная сборка для магазина | `.github/workflows/release.yml` (новый файл) |

Почему они здесь: автоматизация не имеет права создавать и менять файлы в `.github/workflows/`
без отдельного разрешения GitHub.

## Способ 1 — попросить AI (1 минута)

Написать в диалоге: «подключись к репозиторию через device flow».
AI выдаст короткий код и ссылку https://github.com/login/device — после подтверждения
он перенесёт оба файла сам и удалит папку `ci/`.

## Способ 2 — вручную через сайт GitHub

Для каждого файла:

1. Открыть файл в репозитории, нажать кнопку **Raw**, выделить весь текст и скопировать.
2. Открыть https://github.com/Help-yourself-dvp/water-filter/new/arena/01a00e70-water-filter
3. В поле имени файла ввести путь: `.github/workflows/build.yml` (или `release.yml`).
4. Вставить текст, внизу нажать **Commit changes**.
5. После переноса обоих файлов удалить папку `ci/`.

## Что изменилось в build.yml по сравнению с текущим

- версия берётся из `version.json`, а не вбита в трёх местах вручную;
- сборка падает, если версия в `index.html` разошлась с `version.json`;
- перед сборкой прогоняется быстрая самопроверка `tools/selftest.js`;
- иконки собираются из четырёх подготовленных файлов (одинаковый вид в лаунчере,
  в списке приложений настроек телефона и в шторке уведомлений);
- приложение больше не открывает системные экраны разрешений при первом запуске.
